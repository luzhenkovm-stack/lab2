# Отчёт по лабораторной работе №2

**Тема:** Интерфейсы. Репозиторий. JSON.

**Цель работы:** освоить интерфейсы C#, принцип разделения интерфейсов, полиморфизм, паттерн Repository, работу с SQLite и создание REST API с JSON.

## 1. Выполнение работы

### Часть 1. Интерфейсы

Созданы интерфейсы `IMovable`, `IDrawable`, `IShape`, `I3DShape`, `IPrinter`, `IScanner`, `IFax`, `IPayable`, `ILogger`. Реализованы классы `Point`, `Circle`, `Rectangle`, `Cube`, `Printer`, `Scanner`, `MultifunctionDevice`, `CreditCard`, `Cash`, `ConsoleLogger`, `FileLogger`. Для демонстрации нарушения ISP создан интерфейс `IDevice` и реализации с пустыми неподдерживаемыми методами. Метод `DrawingService.DrawAll` принимает коллекцию `List<IDrawable>`, а `ShapeInfoPrinter.PrintShapeInfo` работает с любой фигурой через `IShape`.

### Часть 2. Паттерн Repository

Выбрана предметная область «Каталог книг». Сущность `Book` содержит идентификатор, название, автора и цену. Для хранения используется SQLite и Entity Framework Core. Созданы обобщённые интерфейсы и классы репозитория, специализированный `IBookRepository` с поиском по автору, диапазону цен, а также `UnitOfWork`. Поддерживаются CRUD- и асинхронные операции.

### Часть 3. JSON и REST API

Создана таблица `User` с полями `Id`, `Login`, `PassHash`. Реализованы маршруты `POST /user`, `GET /user/{id}`, `PUT /user/{id}`, `DELETE /user/{id}`. Данные передаются и возвращаются в JSON. Добавлены проверки обязательных полей и уникальности логина. Хеш пароля не включается в ответы API.

## 2. Результаты выполнения

Ожидаемое поведение при запуске проекта:
- демонстрация интерфейсов выводит координаты точки, операции рисования фигур, геометрические характеристики, работу МФУ, оплату и сообщения логгера;
- при первом старте создаётся SQLite база `lab02.db`;
- REST API создаёт пользователя и возвращает HTTP 201, читает его с HTTP 200, обновляет с HTTP 200 и удаляет с HTTP 200;
- повтор логина возвращает HTTP 409, некорректный запрос — HTTP 400, неизвестный ID — HTTP 404.

Фактический запуск в среде подготовки отчёта не выполнялся, так как .NET SDK недоступен. Команды проверки приведены в README.

## 3. Ответы на контрольные вопросы

1. Интерфейс — контракт, определяющий набор членов, которые должен реализовать тип.
2. Нет, экземпляр интерфейса напрямую создать нельзя. Переменная интерфейсного типа может ссылаться на объект класса, реализующего этот интерфейс.
3. Полиморфизм позволяет обрабатывать разные реализации единым способом через общий интерфейс.
4. Интерфейс задаёт контракт; абстрактный класс может содержать состояние, конструкторы и общую реализацию. Класс может реализовать несколько интерфейсов, но иметь только один базовый класс.
5. ISP требует разделять крупные интерфейсы на небольшие специализированные, чтобы клиент не зависел от ненужных ему методов.
6. Примеры: способы оплаты, устройства печати и сканирования, логгеры, объекты, которые можно перемещать.

## 4. Схема таблиц

`User(Id INTEGER PRIMARY KEY, Login TEXT UNIQUE NOT NULL, PassHash TEXT NOT NULL)`

`Books(Id INTEGER PRIMARY KEY, Title TEXT NOT NULL, Author TEXT NOT NULL, Price DECIMAL NOT NULL)`

Между таблицами нет внешних ключей, поскольку выбранные сущности независимы.

## 5. Выводы о применимости Repository

Repository скрывает детали доступа к данным за интерфейсом. Это позволяет бизнес-логике не зависеть от Entity Framework и конкретной СУБД. GenericRepository уменьшает повторение стандартных CRUD-операций, специализированный репозиторий предоставляет запросы предметной области, а Unit of Work координирует сохранение изменений нескольких репозиториев через один контекст.

В ходе лабораторной работы рассмотрены интерфейсы, полиморфизм и ISP, реализован паттерн Repository с Entity Framework Core и SQLite, а также разработан REST API с JSON. Полученные решения демонстрируют разделение ответственности, повторное использование кода и стандартизированное взаимодействие с данными.
